# Slice history

What each slice changed, newest first. All are done and all are deployed: slices 1 to 17 went out
as `v1.0`, **slices 18 to 29 as `v2.0`**, and **30 and 31 as `v2.1`**, all on 2026-09-22 for the
last two (State has the deploy truth). Before
`v2.0`, three reviews -- code, security, and SPEC against the build -- found two things that must
not ship (the retry probe deleted thought logs; model-written markdown could make the browser
fetch a remote URL) and five real bugs. All seven were fixed, each with a test or a browser
reproduction, and the whole eval suite passed in one run on the pinned model.

Deployed is not the same as accepted. **Slices 18 to 22 were seen and accepted on a device**
before `v2.0`. **Slices 23 to 29 first reached a device with `v2.0` and are not accepted yet**:
four questions only a phone can settle are still open, and the first day's use turned up
problems, all fixed on `main` since, the last of them by slice 31 (State, Open).
Until they are answered, 23 to 29 are built, tested and live, and no more than that. Current truth lives in
`SPEC.md` (product), `../knowledge/technical.md` (how it is built), and `../knowledge/rules.md`
(hard rules). Where a slice below disagrees with those, they win; the full plans are in git.

Scope rules changed on 2026-09-17: rule 4 stopped banning push and pomodoro, and SPEC's Out of
scope list dropped the ask feature and the Claude fallback, both of which had already shipped.

- **34 · suggest links for items already filed** (2026-09-23, not deployed) A server command, `python -m tartib.suggest_links --space NAME`, asks the classifier which similar items each filed note or task should link to and sends the ones with answers back to Needs attention as `relink`, links as chips; approving files an item back exactly as it was, with `Related: [[…]]` for the kept ones. One per pair, a skipped pair never again, an unchanged item never asked twice. Proof: `slice-34-suggest-links.md`.
- **33 · links between items** (2026-09-22, not deployed) `[[Title]]` in any item's text opens the item whose first line is Title; `[[space:name]]` opens a space, whose page lists such items under "Linked here" apart from its own. Typing `[[` offers items with their space. Renaming an item or a space rewrites the links to it in the same save; a missing target dims; the target shows "Linked from". The links are an index of the text (migration 0020), rebuilt at startup. Phase C, built the same day **behind `TARTIB_LINK_PROPOSALS`, off**: the classifier may name up to two of the similar items it is shown, the item waits with each as a chip, and approving appends `Related: [[…]]`; off, the prompt is unchanged. Proof: `slice-33-links.md`.
- **32 · Pick for me** (2026-09-22, not deployed) Today was empty whenever nothing was due or starred. A button on the Today card now asks the AI, on demand and with an optional steer, to star up to three open tasks not already there, with the reason as a thought on each. A pick's stars are marked (`picked_at`) and the next pick takes them back; touching a star makes it yours. Nothing changes unless the reply names a real candidate. Tasks only, by the owner's choice. Proof: `slice-32-pick-for-me.md`.
- **31 · one title, one control shape, questions in a modal** (2026-09-22, deployed as `v2.1`) Three first-day reports. The switches in "+ Add", a space's policy and the chime were `.seg` beside fully rounded pills; they are the pills now, and `.seg` is gone. The title stopped being a separate field shown three times and editable once: **the first line is the title**, shown once and drawn as one in the rendered text and the editor alike, and `title` became a column derived from it on every write, so reminders, sessions, Ask and the classifier's context needed no change. The AI's task title is added above the text when it says something different -- the owner's choice over dropping titles, and rule 1's first exception -- and migration 0018 did the same to existing tasks with the touch trigger lifted, so `updated_at` did not move (25 of 40 locally). And every question asks in a modal now, the app's first: deletes, the session outcome (once per session, with Later), the stale save (which cannot be dismissed), Sign out and Clear house rules. The browser pass found a bug older than the slice: on a phone a space's four header controls ran 428px wide and pushed Delete off the screen, invisible to the overflow check because the page clips. Four fixes that had been proved by scratch scripts and thrown away went into the committed UI suite with it.
- **30 · a split waits for you** (2026-09-22, deployed as `v2.1`) On `v2.0`'s first day two pasted notes were split line by line and every piece filed itself at 0.97+: a heading over nine preferences became nine notes with the heading in none. Now a capture that splits files none of its pieces -- each waits as `split` -- and **Keep as one** replaces them with one waiting note from the capture's whole text, while no piece has been started on. The prompt now says a heading over lines is one note; one targeted eval on the pinned model kept both captures whole and still split "call Ali, buy milk". The plan's cheap trick for "untouched", `updated_at = classified_at`, was right in idea and wrong in precision: at second resolution a fresh row sorted after an edit made a moment later, and an existing test caught it.
- **29 · what the AI costs** (2026-09-22) Tartib ran a subprocess for every capture and knew nothing about it. Now a row per call: kind, model, six token counts, duration, and the CLI's own words when it fails -- with the subscription limit as its own kind of failure, reset time and all, after it stopped work four times in two days with the app none the wiser. The predicted regression arrived immediately and an existing test caught it: `--json` turns stdout into JSONL, and stdout was where the error message came from, so the text that makes a stalled run diagnosable became a JSON blob until the parser took it from the error event instead. The cost is computed and deliberately **not shown**: pricing reasoning tokens alongside output would bill them twice, and that reading is unconfirmed, so the API carries `cost_verified: false` and the UI suite asserts no money appears while it is. One deliberate call settled all three open questions and corrected two of them: the CLI reports **no total** (so every row would have stored a zero -- a bug only a real call could show, since the fake was written from the field list), reasoning comes back 0 so the double-count risk never arises, and there is no `token_count` event in exec mode, leaving the quota readout built and dormant. It also revealed the real cost of a capture: **15,600 input tokens, of which only ~2,400 is Tartib's prompt** -- the rest is the CLI's own instructions on every call, which is what has actually been eating the subscription. Prices ship in code and refresh at most daily, keeping four numbers rather than a 5MB catalogue.
- **28 · what the classifier may name** (2026-09-21, closed 2026-09-22) The classifier could describe things but not point at them. It can now name a **duplicate** -- candidates retrieved per capture, which slice 26 had not done whatever the backlog claimed, and named by **ordinal, never an id**: an invented ordinal resolves to nothing with no validation rule at all, while an invented id can be a real item it was never shown. 3/3 duplicates caught and 0/5 near misses, every reference resolving. Parking sits behind a flag, default off, with the verdict recorded from day one so it can be judged on real captures first; migration 0015 is additive, and `attention` now says which of its three reasons it is. It can also **propose a space that does not exist** -- a proposal only, where accepting is what creates it. The one thing the plan did not foresee was in the test: a house-rule control sat on the fence and was measuring its own wobble, and the assertion predated slice 27, treating a capture that declines to guess as drift. The code was right and the test was wrong, which is worth remembering because the reflex after slice 27 was to reach for the prompt.
- **27 · the AI contract** (2026-09-21) Three things you could not say to the classifier before. **House rules**: your own filing rules in your words, appended to the shipped prompt and never substituted into it, so a bad rule gives bad advice rather than stopping every capture from filing -- measured at 0/3 to 3/3 on captures the model would not have filed that way unaided, with no drift onto unrelated ones. **A question instead of a guess**: one field, one question, two to six answers as buttons, carried in `proposal_json` with no migration; an option naming a space that does not exist is dropped, and an item that asks never files itself. **Corrections as examples**: up to five, corrections first, padded only with high-confidence accepted items, and only a field the classifier itself proposed may count -- otherwise it learns from our own filing fallbacks. Three sabotages each turn a test red. The readout reads 0 corrections, which is the honest state of the data and exactly what earlier work predicted. Getting it to ask in the *right* cases took two measured rounds: told only that a null space should become a question, the model made nulling comfortable and started asking about captures it had always filed. The counterweight -- asking is not a way to avoid choosing -- restored both directions at once, and the eval that had passed while it never asked at all now requires both halves.
- **26 · retrieval** (2026-09-21) The retrieval half of 14, taken out and done first. The classifier is now shown what already lives in each space -- counts and the most recent few items, built server-side by `store.classify_context` -- which took six deliberately ambiguous captures from **0/6 to 6/6** on space, measured on this build. Ask expands: when a question's own words match nothing and the database holds more, Codex proposes 3 to 5 search terms and retrieval runs again, one extra call spent only where the cheap path failed. Ask also carries one turn, so "what about the second one?" has a referent. `store.item_header` became the one owner of what an item looks like to both prompts, closing the backlog's "shared rules" entry by building the thing that would have duplicated them. The UI harness stopped being thrown away: `frontend/tools/ui/check.mjs` is committed and caught a 38x44 tap target on its first run.
- **25 · offline** (2026-09-21) The app used to go blank of data the moment the network did -- the shell opened and a capture still queued, but every screen was empty, because the worker returned early for every `/api/` path. It caches those reads now, network-first, so online nothing changes and offline the stored copy answers; sessions are left out, because a countdown is only true at the moment it is read. Every screen loads through one hook, so the line saying how old the data is got written once. Then the four things you actually do with a note in your hand: tick it, star it, edit its text, add a thought. They queue when the network will not take them, replay on reconnect, and are laid over the cached data as screens read it, so the box stays ticked and the row says "waiting to send" -- ticking a box and watching it untick is the behaviour people file bugs about. Two traps in the existing code were avoided and proved: activation deleted every cache but one, which would have wiped the new one on every update, and the IndexedDB upgrade to v2 is additive, checked against a database seeded at v1 with an unsent capture in it. One thing the plan missed: the editor is a lazy chunk and the worker only caches what it has fetched, so editing text offline was impossible until it was warmed on idle -- which narrowed a guarantee slice 24 had made, so that slice's check changed with it. Counts lag by decision; the alternative was reimplementing the server's aggregation in the client.
- **24 · presentation** (2026-09-21) Markdown, in two phases. It renders from marked's token stream straight into React elements rather than through `dangerouslySetInnerHTML`, which turned out to settle two things at once: raw HTML in a note, a brief or an Ask answer can never become markup -- and briefs and answers are written by the model -- while slice 20's search mark becomes a branch in the renderer instead of a pass over output someone else built. On the item body, thought entries, Ask answers and the space brief; row headlines flattened in all five places that compute one. Then the item text stopped being a mode you enter: the Edit button is gone, tapping the words is the gesture, and CodeMirror arrives as its own lazy chunk so a note you only read never pays the 214kB for it. A heading stays heading-sized while you type it, which is the whole reason it is not a textarea. Saving is debounced, on the owner's call against the recommendation, which is why it is flushed on blur, on unmount and on the way out, sends before it touches React state, and pauses rather than retrying when slice 19's stale check refuses -- a non-modal strip, your words untouched. Three things it got wrong first and proved otherwise: mapping a tap by coordinates cannot work across two layouts (it maps by word), `keepalive` is not a guarantee (measured never arriving; the draft is mirrored to localStorage as you type), and a state update before the fetch can cost you the fetch.
- **23 · the UI language** (2026-09-20) Six palettes, then eight, thirteen, ten -- all scrapped, because the problem was never the colours. Shown screenshots of an earlier build, the owner named it: the font, the borders, the chips, the button style. So: JetBrains Mono bundled and used everywhere, one theme (bronze) with the theme system deleted outright, controls reduced to one shape (a bordered pill, mono caps, one filled primary per screen), chips and status tones sharing a single rule, a `TARTIB // TODAY` breadcrumb on every page, a row of stat tiles on Home, and the spaces grid turned into a list with bars sized against the fullest space. It also fixed a live AA failure the theme work uncovered (the session button was white on red at 2.53:1, now 5.21:1) and the defect behind three rounds of complaints about the app bar: the header had been sticky since slice 18, so everything scrolled underneath it and hid behind a translucent band. It scrolls away now. Themes returned at the end and were dropped again the same day, leaving the thing worth keeping: a generator that enforces the contrast floors, which caught a --danger at 3.93:1 and an --accent-2 used as text. The page background became two accent glows and a dot grid, measured where they overlap rather than against the flat colour.
